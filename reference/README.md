# Reference

Five pages that the weekly tutorials assume and do not repeat. Read them when the
week tells you to, or when something on this list is the thing in your way.

| Page | Read it when |
|---|---|
| [`files.md`](files.md) — **Files, folders and the dot** | Before week 1 if the terminal is new to you, and again the first time a file "is not there". Ten minutes: `cd`, `ls`, paths, and the names that start with a dot. |
| [`git.md`](git.md) — **Git, the six commands you use** | After week 1, once you have pushed something and want to know what you actually did. The six commands, what `origin` is, branches, and why the check counts your commits. |
| [`uv.md`](uv.md) — **`uv run`, and nothing else** | Before week 2, or the first time a script needs a library. What `uv run` does, what the `# /// script` block is for, and why the course never says `python` or `pip`. |
| [`python.md`](python.md) — **Python, as far as we have got** | When an assistant hands you code and you want to know which lines the course has covered. Every construct taught so far, in order, with the slide it came from, and the list of things to be suspicious of. |
| [`errors.md`](errors.md) — **When it goes wrong** | The moment red text appears. The dictionary: the exact message, what it means, what to do. Terminal, uv, git, GitHub, Python. |

Nothing here is new material. It is the stuff each week leans on, written down
once so the tutorials can get on with the work.
